# Renderer reference contract

English | [中文](renderer-spec.zh.md)

## Authority and scope

The unchanged TypeScript implementation and its existing tests are the oracle. [renderer-spec.json](renderer-spec.json) records every entry-point value/type export and verbatim built declarations (including signatures, options, class methods and return types); module-only exports in those declarations are not additional public API. Rebuild before checking or recording the snapshot. This document specifies preservation, not a new renderer API.

The tooling-only Zod schema in `tools/renderer-schema.mjs` accepts strictly normalized plain presentation data. Its discriminated operations contain text, columns, frame rows/labels, ordered SGR parameters, markdown calls or screen calls; unknown fields fail. No Cordis context, DSH events, services, jobs, sessions, provider routes, callbacks or host objects belong in Rust. The normalized schema deliberately covers a subset of the public API. Only bounded integral cases passing the resource admission below cross this boundary; direct public TS API semantics remain unchanged. Rejected normalized work must not be automatically retried through an unbounded TS fallback.

## Identity, freshness and resource admission

Every snapshot and capture records source digests (including generated width tables), executed JS/declaration build digests, and compiler-version metadata/config digests. SHA-256 hashes sorted filename, NUL, file bytes, NUL. Tools re-emit JS and declarations with the repository’s existing tsc into an isolated temporary directory and compare artifact digests byte-for-byte; stale or modified builds hard-fail before capture. Verified JS and declaration bytes are copied to a unique temporary module graph with an explicit ESM package type and a matching build digest, then dynamically loaded; preexisting entry or dependency caches cannot supply executed code; every capture rechecks digests, and in-process code changes require restart rather than labeling old ESM cache with new file hashes. The API extractor fails closed on unfamiliar entry-point syntax. Isolated-copy tests mutate behavioral source and executed JS independently and prove both are detected; production source is never mutated. A separate isolated-copy regression preloads the old module graph, validly rebuilds changed behavior, then verifies capture executes the new behavior.

Admission limits: 2048 UTF-16 units per string; 64 entries per collection, call sequence, case list and palette role table; 16 parameters per SGR array; `codePointWidth.code` admits integers 0 through 0x10FFFF (all Unicode scalar values and the surrogate code-unit range preserved by TS); other integers remain -9999 through 9999; column budgets additionally -256 through 256, screen dimensions 0 through 256. Aggregate input string units (including field names) are at most 8192; explicitly provided files are limited to 1048576 bytes before reading and JSON parsing. Conservative output/work estimate per operation is `(stringValueUnits + min(maxAbsNumericValue, 256) + arrayEntries + 1)^2 * 1024`; `codePointWidth.code` is a lookup key, not an allocation width, and contributes zero to `maxAbsNumericValue`; capture sums case estimates, at most 67108864. The factor covers tab/control expansion, ordered SGR, repeated row replay and screen calls; input palettes additionally obey field and aggregate-input bounds. Over-budget work is rejected before any rendering call. Admission is deliberately conservative and may reject actually cheap requests; it does not redefine public API behavior.

The pure markdown ABI success envelope is exactly `{ok:true,value:{state,rows}}`; failure is `{ok:false,error:{code,fallbackEligible:false}}`, with code only `INVALID_INPUT`, `RESOURCE_LIMIT` or `BACKEND_FAILURE`. Validate inputs, outputs and aggregate budgets; output overrun returns RESOURCE_LIMIT without partial values. The capture CLI uses the same outer shape but value is the complete capture and reference-tool failure code is `REFERENCE_FAILURE`; errors contain no raw content. Low-level `capture` may throw; `captureResult` is the stable result interface. Neither auto nor forced rust may send admission failures or native resource errors to unchecked TS; auto may choose TS for an already-admitted request when the backend is unavailable. Forced rust backend unavailability returns BACKEND_FAILURE. Direct existing TS API calls are not constrained by the new schema. Phase 1 specifies this selection policy without implementing a selector.

## Unicode and UTF-16

Use `packages/renderer/src/width-tables.ts` as the authoritative wide/zero-width ranges, not a library's grapheme widths. C0/C1 controls have zero width; printable ASCII one; zero-width ranges zero; W/F ranges two; everything else one. Supplementary-plane characters are not uniformly one column: emoji may be two, supplementary letters one. Width is a sum of code points, not extended grapheme clusters. ZWJ families, modifiers and regional indicators retain the existing individual widths. No Unicode normalization is allowed.

JS strings are sequences of UTF-16 units. A valid surrogate pair is one code point; an unpaired high or low surrogate is preserved as its exact original unit and measures one column. JSON escaped strings round-trip these units. A later native transport must use lossless UTF-16 units or explicitly fall back to TS for strings it cannot preserve; converting through Rust UTF-8 replacement characters is not equivalent. Cuts never split valid pairs. Host stream UTF-8 encoding, including its replacement of malformed units, remains a Node I/O boundary, not part of the pure string result.

## ANSI, styling and cuts

The exact recognized escape grammar is the `ANSI_PATTERN` in `width.ts`: CSI numeric/semicolon/question-mark parameters and intermediate bytes, or OSC terminated by BEL or ESC-backslash. Do not substitute a more permissive terminal parser. Unrecognized/bare ESC remains a zero-width character/token with the existing replay behavior; following printable characters still count. `stripAnsi` removes only complete matching sequences. Only `CSI m` and `CSI 0 m` close tracked styling. Other escapes, including foreground-only reset, append to the replay state in order. This is byte-level compatibility, not an SGR semantic optimizer.

`truncateToWidth` returns empty for nonpositive budgets, retains zero-width runs after the last fitting character, stops before the first overflowing character, and adds full reset only when a cut discards open styling. An uncut string is unchanged. `tailToWidth` preserves a suffix without reopening styles from before the cut and drops orphan leading zero-width characters after a real cut, retaining escapes. `fitToWidth` pads after whole-wide-character cuts. `chunkToWidth` hard-breaks; `wrapToWidth` prefers spaces, discards the chosen separator and continuation-leading spaces, and preserves first-row indentation. Both replay opening escapes and close rows with full reset; their edge cases differ (including a too-wide first glyph and empty paragraphs), so do not unify them. `hangingIndent` reserves the larger gutter and clips an overflowing composed row.

Escape untrusted content before adding styling, per row. `escapeControls` keeps LF, caret-escapes C0/DEL, spells C1 as backslash-u braces, expands tabs to eight-position stops counted by code points after escaping, not display columns. `sanitizePasted` first normalizes CR/CRLF to LF and tabs to four spaces. `sgr` preserves parameter order and ends with full reset; empty parameters return text unchanged. The palette wrapper owns mutable process-global state, fallback selection and idempotent restoration. Depth zero removes all styling, missing roles are unstyled, role parameter arrays concatenate in caller order.

Screen erases use `CSI 0K`/`CSI 0J` exactly; back-color erase (BCE) follows the terminal's active rendition. No extra reset, palette-background fill or alternate-screen mode may be inserted to “correct” BCE. Emulator tests must examine cells/attributes and cursor, not only stripped text.

Palette snapshots contain already-resolved ordered SGR arrays by opaque role key, plus id and depth (0, 4, 8 or 24). Host TS folds authored truecolor/ansi256/ansi tables before the native call; native rendering performs no terminal detection or nearest-color approximation. Missing roles contribute no parameters; depth zero contributes no styling. Capture accepts an optional resolved snapshot and always records the effective snapshot in its output; omission uses the explicit exported markdown defaults at depth 4. This makes colored outputs reproducible independently of process-global palette state.

## Frames and markdown

`box` and `frame` are different published primitives. Preserve minimum width five, four-column chrome, wrapping, padding and height results. `frame` truncates width to an integer, flattens label newlines, gives left title priority over right title, and integrates footer/dividers without extra label rows. `box` does not acquire `frame`'s coercion or label rules. Callback-based border styling remains a TS API: normalized capture represents only the explicit `sgr` callback subset through ordered `border` parameters; arbitrary callbacks never cross native code.

Markdown is the repository's terminal-oriented dialect, not a CommonMark replacement: headings, rules, quotes, lists, literal fences and inline link/code/emphasis rules remain exactly those in `markdown.ts` and its tests. Unknown/malformed constructs remain visible and escaped. Link output includes the parenthesized target. Fence state keeps marker character and complete opening run; only a same-character equal-or-longer marker with no info string closes it. Completed `line` calls advance state; `partial` observes but never changes it. A clipped partial (`startsLine=false`) is literal, except existing fence styling. Splitting a document on LF includes the final empty source line. Delimiter/flanking checks and UTF-16 indexing must preserve supplementary characters.

## State and host boundary

Phase 1 changes no runtime dispatch. The planned native transformation set is width/ANSI scanning and cuts, escaping/paste normalization, explicit SGR emission, frame/box geometry and pure markdown line transformation with explicit fence state. TS remains reference and fallback. `style` and `paint` stay TS wrappers resolving names/roles to ordered SGR parameters. `paintGlint`, spinner/elapsed/token formatting may call native width/cuts but their orchestration remains TS. Composer buffer/history/folds/actions, `layoutComposer` projection and inverse mappings, key decoding and terminal acquisition remain TS. They may use native width/cuts without transferring their state machines. No composer callbacks or mapping closures cross the boundary.

`createMarkdownRenderer` retains document state in TS. The specified pure native markdown transition accepts `{state: {fence: string|null}, palette: {id, depth, roles}, text, mode: "line"|"partial", startsLine: boolean}` and returns `{state: {fence: string|null}, rows: string[]}`. The fence is null or the complete opening backtick/tilde run (at least three equal markers). `line` recognizes at most three opening spaces, then a run and trailing info: outside a fence it records the full run and emits the trimmed nonempty info in muted styling; inside a fence it closes only for the same marker, equal-or-longer run and empty trimmed info. Otherwise state stays unchanged. `partial` always returns the identical incoming state; with `startsLine=false`, emit literal escaped prose or the existing indented code styling, never syntax-parse a suffix. For partial, rows equal the existing wrapper string as one array entry (including an empty string); line rows equal the existing `line` result. The TS wrapper joins partial rows to preserve its string return type. The machine-readable schemas specify both transition sides; Phase 1 implements no native transition or dispatch. `renderMarkdown` remains the TS document loop. Screen remains the sole TS terminal writer and live-region state owner; only wrapping is eligible for native dispatch. Capture's `screenSequence` is a reference-observation recipe, not a proposal for a native screen service.

Screen commits immutable scrollback above the live area, wraps at current width floored to one, ignores empty commits, and redraws saved live rows. Identical wrapped rows/cursor/width skip writes only while current. Cursor row clamps to the live area and column floors at zero. `markStale` invalidates trust but keeps drawn geometry. Resize erases using cached drawn height, never reflowed history; terminal-driven reflow can still scroll old pixels before notification. Preserve synchronized-update, hide/show cursor, CR/LF and per-row erase sequences exactly. `close` clears cached geometry in `finally`, even on sink error. I/O errors, stream encoding, raw mode, terminal modes, timers, dimensions, key subscriptions and resize notifications stay host-owned in TS.

## Capture and remaining evidence

Build, then run the deterministic synthetic capture or explicitly provide a normalized observation. Output contains normalized inputs, provenance, actual live TypeScript return values and per-call Screen write strings/heights. Synthetic inputs are labeled synthetic even though their outputs are observed calls. No raw logs, profile paths, automatic session enumeration, credentials or private sessions are read. Session observation is opt-in by an explicitly named JSON file with `observed` provenance and `explicitly-provided-normalized-data` consent; the caller must normalize/redact it first. The tool never infers renderer inputs from DSH events.

```sh
pnpm build
node tools/renderer-spec.mjs --write
node tools/renderer-spec.mjs
node tools/renderer-capture.mjs --synthetic /tmp/renderer-capture.json
node tools/renderer-capture.mjs --session-input /tmp/normalized-observation.json > /tmp/observed-capture.json
```

Phase 1 includes a capture mechanism and a small deterministic demonstration, not the Phase 2 broad corpus or differential harness. Remaining evidence: representative consented normalized session samples, broader palette-depth/custom-role cases, full malformed-ANSI matrix, composer projection/keyboard host regressions, terminal resize/BCE attributes and performance workloads. Phase 2 must add that evidence before any Rust library defaults or transport decisions can be accepted. Existing emulator and renderer tests remain authoritative; API snapshot checks cannot replace behavioral tests.
