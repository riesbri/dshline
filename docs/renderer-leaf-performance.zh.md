# 原生叶子函数查找表实现

[English](renderer-leaf-performance.md) | 中文

> **后续修订：** 下文数据保留为新增回归守卫之前的历史记录。[后续报告](renderer-leaf-followup.zh.md)说明 TS 默认路径、运行时与已编译 Unicode 版本耦合、同轮回归复现和真实 PTY 流式整轮计时。

## 范围

本次实现针对已审查的渲染器基线 `5e48b70`，落实
[研究 PR 301](https://github.com/riesbri/dshline/pull/301) 中的仅查找表和无循环依赖
原生叶子函数提案。不采用已被拒绝的两遍扫描尾部算法或 ASCII 换行，不扩大原生
接纳范围，也不将宿主所有权移入 Rust。

`native-primitives.ts` 拥有现有可选加载器、进程渲染模式和带守卫的直接操作，
仅依赖未改变的 TS 宽度策略与 Node 模块加载器。`backend.ts` 在复合和 Markdown
派发中复用该选择。Screen 及 box/frame 内部导入基础函数 seam；不存在反向导入
复合层的路径，并测试运行时图无循环。TypeScript 仍拥有回调、可变对象、调色板、
文档状态、终端写入、滚动缓冲区和生命周期。Harness 拥有所有 agent 状态。

## 派生查找表

生成器仅读取已提交的 Unicode 宽度策略，不依赖网络或构建。生成 4352 个单字节
索引和 108 个独特的 256 字节页：**32000 字节表数据**，小于研究原型的双字节
索引。未来策略若需要超过 256 页，生成会失败，而不是截断索引。原始 Rust 范围
仍是独立的测试基准，并穷举比较每个 Unicode 码点。ANSI 扫描、控制字符优先级、
孤立代理项及库对域外输入的行为保持不变。构建和 CI 拒绝过期生成数据。

首轮生产路径测量发现编译形态退化：小查找表被自动内联进显示扫描器，使 Linux
ARM64 的纯 ASCII 宽度/填充变慢 10–25%。在专项探针中，将 `code_point_width`
保持为非内联调用恢复了 ASCII 和末尾 CJK 的基线行为，同时保留大幅 Unicode
收益。分离辅助函数的变体改善了部分 token 变换，却使填充退化，因此未保留。
下方最终重复测量在每个平台评估此控制；原始结果仍标记为初始/填充优化前，
而不是悄悄覆盖。

## 有界填充后续优化

首轮 Intel 复测恢复了 ASCII 宽度，却暴露长行 `fit` 退化。保留的后续优化复用
现有截断器测得的精确前缀宽度来填充。输入长度超过列预算四倍时，不再扫描将被
丢弃的后缀；短行/已适配行保留一次宽度扫描与复制。零列保留完全零宽的源串，
负预算仍返回空串。不改变 API、接纳或宿主所有权。

独立参考检查还在本地 Node 24.18 上复现了以孤立高代理项结尾的切片字符串的 TS
宽度随字符串表示变化的问题。扫描器现在从用于 token 跨度的同一组有界 UTF-16
单元推导码点，不再独立使用 `codePointAt` 读取。保留既定码点求和策略和无损畸形
单元，并非新的 Unicode 策略。真实进程中的切片/平坦字符串回归测试拒绝旧扫描器，
错误填充变异也使新增 Rust 语义测试失败。这里未确立上游引擎原因或普遍 Node 漏洞。

## 正确性与接纳

现有 auto 阈值、2048 单元输入上限和 ±256 列预算保持不变。缺失产物或不支持的
宿主值在执行前选择 TS。auto 对准入后的后端/panic 失败在 TS 专用选择下恢复一次；
调用方资源/输入错误及所有强制 rust 错误仍直接传播，不重试（[策略](renderer-auto-recovery.zh.md)）。
显式 TS 模式从不调用 addon，包括 Screen/frame 内部。强制 Rust 仍允许宿主回调，
但回调中的已获准标量叶子工作现在进入同一个原生选择器，而非独立宿主实现。

已验证参考快照会在加载宿主模块前显式选择 TS，包括现有基准、持续对比和原生
边界测试中的参考，避免悄悄将原生宿主路径与其自身
比较。声明快照包含传递性重新导出的模块。全部 86 个黄金样例的输入输出保持
不变；仅刷新源码/构建身份。

真实 addon 测试统计宿主原生调用，并在 auto/rust/TS 模式下比较精确写入、回调
观测、模拟器单元格、光标、颜色、过期/收缩/尺寸变化及无操作重绘行为。资源错误
探针证明不会重试；微小、超大和窄输入证明执行前回退。

使用 Node 24.18，托管 Apple M1 (Virtual) 使用 24.20，Intel i7-8700B 使用
24.19。不跨机器比较绝对速度。

最大的内核收益来自长有界填充不再扫描将被丢弃的后缀；原生叶子路由则让现有
Rust 换行真正进入宿主调用路径。追踪配方记录基线宿主原生调用为零，而当前 frame
调用换行/宽度，Screen 调用三次换行。这比只测不可达导出更有力，但仍仅是合成 CPU 证据。

### 退化与未采纳的调优

**并非所有输入都更快。** 120 项负载中，公共 auto 中位数变慢超过 10% 的观测
数量为 Linux 1 项、M1 30 项、Intel 11 项。所有原始样本均保留；这些计数不代表
统计显著性。例如：

- Linux 24 单元 ASCII 回调 frame：4.93 → 5.52 µs（慢 12%）。
- M1 24 单元 CJK 换行：2.30 → 4.18 µs；96 单元 emoji 分块：3.01 → 5.32 µs。
  按既有阈值这些 auto 路径仍使用 TS。M1 2048 单元末尾 CJK 宽度也退化：
  1.73 → 2.06 µs（慢 19%）。
- Intel 512 单元、256 列换行：12.19 → 15.79 µs（慢 29%）；部分尾部截取、
  小填充与 ANSI 换行也变慢。

托管样本轮间变化较大。应视为观测到的权衡，而非全输入或真实会话延迟保证。
不扩大或重调接纳策略来掩盖较慢样例。

临时 ThinLTO 加单代码生成单元在每台 Mac 通过穷举宽度及 10,680 次有界变换比较，
但相对未调优的新构建，中位数慢超过 10% 的负载为 **M1 39/120**、**Intel 31/120**。
因此**不采纳**。保留 panic 展开、可移植 CPU 默认值和最低系统版本。两遍扫描尾部
算法与 ASCII 换行仍不采纳。

## 复现与证据

`tools/renderer-upgrade-bench.mjs --baseline-root <checkout> --output <json>`
要求单独构建精确基线，验证 TS 生成图与 addon 源码/二进制来源，在计时前通过双方
发布 addon 穷举所有码点并追踪原生可达性。每项负载保留八种变化输入、500 次预热、
校准至至少 5 ms 的批次、三轮轮换顺序测量，结束后重新核对身份。不要并行构建/测试。
参考快照在导入宿主前显式选择 TS。

构建和一致性门禁，而不执行昂贵性能步骤。Mac 作业上传
`renderer-upgrade-darwin-arm64` 与 `renderer-upgrade-darwin-x64`。调优二进制不替换打包 addon。

## 验证与限制

源码验证通过六个原生目标、Core Node 22.19/24/26、Harness 已采纳源码及打包消费者、
Windows 启动器、tmux 和文档。Core 在 Node 24/26 有 5,585 通过 / 26 跳过，
Node 22.19 有 5,583 / 28，另通过必需的真实 addon 检查。
[源码安全/CodeQL](https://github.com/riesbri/dshline/actions/runs/38888220985) 通过。
并行 PR 消费者作业触发现有的 10 分钟插件添加超时（pnpm 已输出完成）；相同运行时
提交在完整手动源码验证中通过该作业。除观察到超时外，未确立其他原因，也不延长
超时。最终提交头 CI 会重新执行此契约。本地构建/类型/安全/文档检查
通过；完整本地测试有 **5,582 通过 / 26 跳过**，另有在本机未修改基线上已复现的
三个启动器 pnpm 前置检查失败，未隐藏新失败。真实 addon 专项工具测试 25 项通过；
Rust 有穷举宽度单测和 12 项语义测试。86 个黄金输入/输出均不变。故意错误的查找表、
绕过 Screen 叶子、旧切片扫描器及错误前缀宽度/填充变异均被输出检查拒绝。

宿主模拟器比较精确有序写入、单元格/颜色/光标与回调观测。计时宿主使用内存目标：
不声称 PTY/终端 I/O、整轮提速、泄漏/消毒器或真实 Mac 交互分析结果。本次为自查，
**没有独立审查**；保持草稿。最终报告提交头的检查状态见
[PR 302](https://github.com/riesbri/dshline/pull/302)。
