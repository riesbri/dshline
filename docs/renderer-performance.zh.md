# Rust 渲染器性能调查

[English](renderer-performance.md) | 中文

## 问题所在

第一个 release 附加模块并不因为采用 Rust 就更快。宽度测量为每个字符分配向量及
UTF-16 缓冲区。大多数其他操作还在 JavaScript 中构造数字数组、序列化 JSON、解析
并克隆 serde 值，再序列化和解码结果。原生流式处理把每条已提交行在两种语言中各
完整渲染一次；即使强制 TypeScript，也复制调色板快照。

## 比较过的方案

| 方案 | 发现 | 决定 |
| --- | --- | --- |
| 原始逐调用 JSON 后端 | 边界开销很大，选择器测试超时 | 仅保留给验证和强制复合操作 |
| 借用 token 跨度及无分配宽度扫描 | 消除逐字符所有权/分配，前缀扫描提前结束 | 采用 |
| 直接 UTF-16 napi 方法 | 避免数字数组及 JSON 转换，保留孤立代理项 | 对受支持的有界变换采用 |
| auto 全部采用原生 | 微小查询、前缀截断、窄列行数组可能更慢 | 拒绝全面原生策略 |
| 混合 auto 选择器 | 以低成本长度/预算检查选择测得有收益的路径 | 采用保守阈值 |
| 缓存调色板快照 | 调用方持有的 SGR 数组可能在安装后变化 | 拒绝过期缓存，按需构造快照 |
| 完整 TypeScript 流式影子 | 重复成功的原生渲染 | 改为从明确围栏状态按需恢复 |

## 历史优化测量

测量使用 Linux arm64、树莓派 5/Cortex-A76、Node 24.18.0、Unicode 17.0 上的
release 构建。这些是受 CPU 状态影响的本机微基准，不是跨平台保证，也不能证明
整个模型轮次同比加速。优化前已冻结原始直接附加模块及已编译 TS。

独立调查中的代表性原始直接调用比较：

| 工作负载 | TS 参考（µs） | 优化后直接 Rust（µs） |
| --- | ---: | ---: |
| 宽度，ASCII 2048 单元 | 26.43 | 3.13 |
| 宽度，CJK 2048 单元 | 187.93 | 49.02 |
| 尾部选择，ASCII 2048 单元 / 40 列 | 75.56 | 16.52 |
| 换行，ASCII 2048 单元 / 40 列 | 244.13 | 86.33 |
| 前缀截断，ASCII 2048 / 40 列 | 0.76 | 1.55 |
| 去除 ANSI，普通 ASCII 2048 | 1.39 | 8.46 |

特意列出最后两行：强制 Rust 并非普遍更快。单列窄分块经 napi 最多慢七倍，原因是
构造大量 JavaScript 字符串；auto 将这些路径保留在 TS。

已提交的[公共路径测量数据](../benchmarks/renderer-arm64-2026-10-15.json)比较原公共
自动后端、优化后公共 auto、显式 TS、直接 Rust 及独立 TS 实现。主要变换语料的每个用例采用八个
变化输入（窄列与流式探测重复单个输入），防止单键缓存伪装成普遍提升。计时之前先断言精确输出；缺失原生代码即
硬失败。环境记录包含当前原生及源码摘要。历史基线记录附加模块摘要，但不独立验证
旧 TS 源码/构建来源；因此该比较保留为探索性历史实验，而非最终精确源码就绪证据。
旧基线快照必须含匹配的 `lib/` 和 `native/`。

公共路径比较（ASCII 输入；流式部分使用带样式的双语文本）：

| 操作 / UTF-16 单元 | 原 auto（µs） | 优化后 auto（µs） |
| --- | ---: | ---: |
| displayWidth / 2048 | 28.35 | 3.21 |
| tailToWidth / 2048 | 111.30 | 18.75 |
| wrapToWidth / 192 | 101.16 | 9.02 |
| stream.line / 104 | 128.30 | 10.05 |
| stream.partial / 104 | 108.50 | 10.43 |

## 当前 auto 策略

| 操作 | 原生子集 |
| --- | --- |
| 宽度、尾部选择、适配 | 文本 64–2048 单元；适配/尾部列预算在 ±256 内 |
| 换行 | 文本 64–2048 单元，32–256 列 |
| 分块 | 文本 512–2048 单元，64–256 列 |
| 单码点宽度、前缀截断、去除 ANSI、转义、清洗 | TypeScript |
| 复合框/帧/SGR 和 Markdown | TypeScript；准入范围内仍可显式强制 JSON Rust |

不受支持的宿主对象在被读取、原生代码在被调用之前，就短路选择 TypeScript。
已准入的原生工作失败后不执行无界回退。required-rust 模式强制已准入纯操作，而不是
宿主专用回调或超出有界子集的公共值；后者在准入之前选择 TS。扩大原生使用范围需要
新的边界测量，不能
假设更快的独立内核必然获得端到端收益。Screen、终端写入、输入器、键盘及 Harness
集成仍由 TypeScript 拥有。

## 复现与验证

测量之前以 release 模式构建附加模块并编译 TS。迁移说明描述目前独立的原生文件；
阶段 5 的可选构建脚本见 CONTRIBUTING；不能从这些测量推断跨平台构建已通过。不要把 CPU
基准与完整测试同时运行。

```sh
pnpm build
node tools/build-renderer-native.mjs --required
node tools/renderer-bench.mjs --output /tmp/renderer-bench.json
node tools/renderer-bench.mjs --baseline /path/to/previous-renderer-package --output /tmp/renderer-compare.json
node tools/renderer-soak.mjs 10000
```

每个基准先预热和校准批次，再报告五次批次平均值的中位数和最大值。
`maxBatchMeanNsPerCall` 是五个平均值的最大值，不是测得的单次调用 p95。正确性门禁不
使用时间断言。直接附加模块 soak 要求干净、精确提交的附加模块来源，使用固定种子，
报告实际宽度/UTF-16 长度覆盖及精确比较数量；绑定 TS 源码/构建/编译器、原生输入、
原始二进制来源及工具哈希，并拒绝执行中身份变化；
不声称具有覆盖率插桩、sanitizer、生产流量或无限时长的内存泄漏测试。

本次优化验证包括全部 86 个原生黄金夹具、90000 次有种子的直接变换比较、独立穷尽
检查全部 1114112 个 Unicode 码点宽度，以及独立畸形字符串和状态切换探测。完整
测试为 5560 通过、26 跳过、三个此前已存在的宿主相关启动器前提失败；原生引入的
选择器超时已消失，未调整测试限制。这不表示所有 CI 平台都已通过；六平台构建仍须
独立门禁。

## 最终源码绑定证据（2026-10-16）

[新鲜的 230 用例基准](../benchmarks/renderer-final-arm64-2026-10-16.json)使用干净的
托管 Linux ARM64 release 附加模块及已验证的当前编译 TS，不包含历史基线。其源码/
构建身份与分支一致；[分发证据](../benchmarks/renderer-final-evidence-2026-10-16.json)
保留 CI 实际合并提交 `82d25b11`，验证其树等于 head `740e406`，不重写文件来源。
六平台归档、生成声明、许可证及全部归档内二进制哈希均通过验证。

| 操作 / UTF-16 单元 | 当前 TS 对照（µs） | Auto（µs） |
| --- | ---: | ---: |
| displayWidth / 2048 | 26.85 | 3.19 |
| tailToWidth / 2048 | 66.84 | 17.41 |
| wrapToWidth / 192 | 18.88 | 8.68 |
| stream.line / 104 | 10.74 | 9.70 |
| stream.partial / 104 | 9.78 | 10.15 |

前三行比较公共显式 TS 与公共 auto；流式行比较独立 TS 渲染器与公共 auto。这些是独立
批次中位数，不是精确通用加速比。auto 的流式处理仍使用 TS；保留稍慢的 partial 行，
避免声称普遍加速。本次运行中，选择原生的 auto 用例相对公共 TS 均无退化；微小 TS
封装仍有测量/分派开销。只在此 Linux ARM64 主机测量性能；六平台正确性不代表性能相同。

[修正后的最终 soak](../benchmarks/renderer-final-soak-arm64-2026-10-16.json)通过
2701224 次实际附加模块比较：300000 随机用例及 136 个显式边界用例，每个九种变换。
每个预算（-256、-1、0、1、8、40、120、256）均有 37517 用例。八个预算全部交叉
17 个精确 UTF-16 边界长度，直至 2048，包括分派阈值两侧。回归测试独立固定必需长度，
拒绝预算坍缩及丢失 2048 的故意变异。旧生成器的低位相关性几乎只选择宽度 1；此前
90000/900000 数量是历史比较，不代表均衡覆盖。修正运行报告并复查源码/构建/原生/工具身份。

托管 Core 在 `740e406` 通过：Node 24/26 各 5575 通过、26 跳过；Node 22.19 为
5573 通过、28 跳过。六个 OS/架构目标的必需实际附加模块一致性全部通过。Harness
源码、打包消费者、Windows 启动器、tmux、文档及安全检查通过。两个新增生成器回归
测试本地通过，并将纳入最终工具提交的 CI。最终审查不授权合并或发布；最新 head 的
PR 检查仍是依据。不声称进行了模型轮次、私人 profile、跨平台计时、插桩 fuzz、单次
调用尾延迟或内存泄漏认证。
